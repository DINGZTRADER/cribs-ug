2. Step-by-Step Setup Instructions
Step A: Scaffolding (Terminal Commands)
We use pnpm workspaces for efficiency.
# 1. Create directory
mkdir uganda-rental-platform && cd uganda-rental-platform

# 2. Initialize pnpm
pnpm init

# 3. Create pnpm-workspace.yaml
echo 'packages:
  - "apps/*"
  - "packages/*"' > pnpm-workspace.yaml

# 4. Install Turbo
pnpm add turbo -D -w
Step B: Shared Database Package (packages/database)
This allows both the API (for querying) and the Mobile App (for types, if needed) to understand the data shape. We map the V2 Schema to Prisma.
File: packages/database/prisma/schema.prisma
// Sources: [7-9] - Production Schema V2

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

enum Role {
  tenant
  landlord
  admin
}

enum Status {
  active
  paused
  deleted
}

model User {
  id                String    @id @default(uuid())
  role              Role
  full_name         String
  phone             String    @unique
  email             String?
  badge_score       Int       @default(0)
  created_at        DateTime  @default(now())
  
  // Relations
  tenant_profile    TenantProfile?
  landlord_profile  LandlordProfile?
  properties        Property[]
  subscriptions     Subscription[]
  payments          Payment[]
  
  @@map("users")
}

model Property {
  id              String   @id @default(uuid())
  landlord_id     String
  landlord        User     @relation(fields: [landlord_id], references: [id])
  title           String
  rent_amount     Int
  district        String
  status          Status   @default(active)
  
  // PostGIS support requires raw SQL queries in NestJS, 
  // but we store coordinates here for basic access.
  latitude        Decimal
  longitude       Decimal
  
  images          PropertyImage[]
  visits          Visit[]

  @@index([status, district, rent_amount]) // Composite Index [10]
  @@map("properties")
}

model Subscription {
  id        String   @id @default(uuid())
  user_id   String
  tier      String   // budget, family, premium
  status    String   @default("active")
  end_date  DateTime
  user      User     @relation(fields: [user_id], references: [id])

  @@map("subscriptions")
}

Step E: Docker Configuration (Phase 1 Requirement)
We need a local database that mirrors the Supabase production environment (PostgreSQL + PostGIS).
File: docker-compose.yml (Root)
version: '3.8'
services:
  postgres:
    image: postgis/postgis:15-3.3 # Standard Postgres doesn't have GIS [16]
    ports:
      - "5432:5432"
    environment:
      POSTGRES_USER: user
      POSTGRES_PASSWORD: password
      POSTGRES_DB: rental_db
    volumes:
      - pgdata:/var/lib/postgresql/data

  # Optional: Redis for BullMQ background jobs (Safety Timers) [21]

3. Key "Production Grade" Implementations
To meet your quality requirements, implement these specific configurations:
1. Strict API Contracts (Shared Types)
Create packages/types/src/index.ts. This ensures the Frontend never sends data the Backend rejects.
// Source [3] - API Contracts

export interface CreatePropertyDto {
  title: string;
  rent_amount: number;
  district: string;
  latitude: number;
  longitude: number;
}

export interface SearchResponseDto {
  id: string;
  thumbnail_url: string;
  rent_amount: number;
  landlord: {
    badge_score: number;
    verified: boolean;
  }
}
• Usage:
    ◦ Backend: class CreatePropertyControllerPayload implements CreatePropertyDto
    ◦ Frontend: api.post<CreatePropertyDto>('/properties', data)

In apps/api/src/config/env.validation.ts, enforce the keys mentioned in Source:
import { z } from 'zod';

export const envSchema = z.object({

  SUPABASE_URL: z.string(),
});
